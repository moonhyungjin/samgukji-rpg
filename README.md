# 삼국지 × 전국란스 스타일 전략 RPG — 전투 샌드박스

현재 단계: **전투 엔진, 시뮬레이터, CLI, Balance Lab, PixiJS 전투 화면(관전 + 수동 플레이) 완료.**
처음 오셨다면 [인계 문서](docs/HANDOFF.md)부터 읽는다. 설계 문서는 `docs/design/`, 원본 기획서는 `docs/spec/`에 있다.

## 구조

```text
apps/
  game/            React + PixiJS 전투 화면 (관전, 수동 플레이)
  balance-lab/     React + Vite 밸런스 도구 (시뮬레이션은 Web Worker에서 실행)
packages/
  battle-engine/   순수 TypeScript 전투 엔진 (React/PixiJS/DOM 의존 없음)
  game-data/       병종, 특성, 스킬, 캐릭터, 밸런스 수치, 기본 편성
tools/
  sim/             시뮬레이션 CLI
  e2e/             게임 화면을 실제 브라우저로 조작해 확인하는 스크립트
docs/              HANDOFF.md, design/(설계), spec/(원본 기획서)
```

`battle-engine`은 데이터를 인자로만 받는다. 게임 화면과 Balance Lab이 **같은 엔진**을 쓴다. 화면은 규칙을 계산하지 않고 엔진의 이벤트를 재생하기만 한다.

## 명령어

```bash
npm install
npm test                 # vitest (엔진, 통합, Lab, 게임 로직/패널)
npm run typecheck

npm run game             # 게임 화면 개발 서버 (http://localhost:5174)
npm run game:build       # 게임 프로덕션 빌드 (apps/game/dist)
npm run e2e              # 게임 화면을 실제 브라우저로 조작해 확인 (먼저 npm run game 실행, Edge/Chrome 필요)

npm run lab              # Balance Lab 개발 서버 (Vite). 터미널에 나오는 주소(보통 http://localhost:5173)를 연다
npm run lab:build        # Lab 프로덕션 빌드 (apps/balance-lab/dist)

npm run sim -- --iterations 1000 --seed 1 --out out/report.json
npm run sim -- --lineups random                  # fixed | random (병종/캐릭터별 승률은 random에서 본다)
npm run sim -- --balance my-balance.json         # defaultBalance에 부분 덮어쓰기 (Lab의 "밸런스만 내보내기" 파일)
npm run sim -- --target-policy lowest-troops     # highest-damage(기본) | lowest-troops | random
npm run sim -- --guard-policy never              # protect(기본) | never: 가드를 쓸 수 있는 군단의 AI
npm run sim -- --team-a shu --team-b wei --roles alternate   # alternate | A-attacks | B-attacks
```

`--balance` 예: `{ "heal": { "scale": 25 }, "morale": { "defenderStart": 52 } }`

## 게임 화면 (`apps/game`)

`npm run game`으로 열고, 설정 화면에서 편성, 조작할 진영, 시드, 속도를 고른 뒤 전투를 시작한다.

- **관전**: 양쪽을 AI가 조작한다. 속도 0.5~4배 또는 즉시, 재생 중 "건너뛰기".
- **수동 플레이**: 공격측 또는 방어측을 조작한다. 내 군단의 차례마다 멈추고, 스킬을 고르면 **대상별 예상 피해/반격/격파**와 **가드가 막을 확률**이 나온다. 대상은 목록 버튼이나 화면의 노란 테두리 카드를 눌러 고른다. 대기(AP 소모 없음)와 "남은 전투를 AI에게 맡기기"도 있다.
- **보병은 가드를 쓴다.** "가드" 버튼을 누르면 올린 뒤의 확률이 표시되고, 카드에 "가드 N%" 배지가 뜬다. 상대가 같은 열 아군을 때리면 확률로 대신 맞는다.
- 화면은 임시 도형이다. 공격측은 왼쪽, 방어측은 오른쪽이고 안쪽 열이 전열이다. 상단에 라운드와 사기 바, 카드마다 병력 바와 AP 칸이 보인다.
- 주소 쿼리로 바로 시작할 수 있다: `?control=attacker|defender|watch&a=shu&d=wei&seed=7&speed=0&autostart=1` (속도 0은 즉시)

## Balance Lab

| 탭 | 기능 |
|---|---|
| 시뮬레이션 | 1 / 100 / 1,000 / 10,000회 실행, 편성(고정/무작위), 공방 배정, 대상 선택 AI, **가드 AI**, 시드. **수치를 고치면 자동으로 다시 실행**하고 변화량(%p)을 보여 준다. 결과를 기준으로 고정할 수 있다. 목표 지표 점검(경고), 병종/캐릭터/스킬별 통계(캐릭터별 "막음" 포함) |
| 전투 1회 | 고정 편성으로 한 판을 돌리고 라운드별 로그와 최종 상태를 본다 |
| 밸런스 수치 | 피해/치유/병력/반격/사기/스탯 곡선 |
| 병종 · 특성 · 스킬 | 병종 설정(**병력 배율**, **가드 켜기와 수치** 포함), 특성 추가/삭제와 병종에 붙이기, 스킬 수치(가드로 막힘 여부) |
| 캐릭터 | 스탯, AP, 레벨, 병종 |
| 목표 · 가져오기 | 목표 지표 범위(기본: 궁병 생존율 20% ±10%p), JSON 가져오기/내보내기, 초기화 |

- 상태는 브라우저 localStorage에 자동 저장된다 (키 `samgukji-balance-lab-v4`. 기본 데이터가 바뀌면 키를 올려 옛 저장값을 버린다).
- **Lab에서 고친 값은 `packages/game-data`의 코드에 자동 반영되지 않는다.** 채택할 값은 "밸런스만 내보내기"(CLI `--balance`로 검증 가능)나 "전체 상태 내보내기"로 꺼내서 옮겨야 한다.
- 실제 브라우저(Edge 헤드리스)에서 확인했다 (가드 열 추가 전): 워커 자동 실행, 수치를 고치면 결과와 변화량이 갱신되는 것, 모든 탭 렌더링, 전투 1회 로그, 콘솔 오류 없음. (가드/버프 관련 열과 입력란이 생긴 뒤에는 서버 렌더링 테스트로만 확인했고 브라우저에서 다시 열어 보지는 않았다.)

## 구현된 규칙

- 라운드제 + AP 총량, 속도순 행동, 동률은 시드 난수로 결정 (재현 가능)
- 커맨드: 일반공격 / 치유 / **가드** / **버프** / 대기
- 상호 피해(반격): 근접 일반공격만 반격을 받고 원거리(화살/책략/독연)는 일방적으로 공격
- **가드**: 보병이 처음부터 쓴다. 같은 열 아군을 대신 맞을 확률 (시작 50%p, 가드 +70%p, 막을 때 −40%p, 공격하면 해제). 책략/독연은 막지 못한다. 규칙은 `docs/design/02-battle-rules.md` 4장
- **상성표 없음, 현재 병종 특성도 없음** (순수 스탯 싸움). 특성 체계는 구현돼 있고 Lab에서 붙여 볼 수 있다
- 병력 비례 피해, 전열 전멸 시 후열이 전열로 이동
- **버프**: 책사 "독려"는 아군 하나의 공격 +1, 도사 "결계"는 방어 +1 (AP 1, 전투 끝까지, 한 아군에게 1회). 병력을 회복하는 대신 아군을 돕는다
- 병종별 병력 배율: 풍수사 0.6, 책사 0.8, 기병 0.8, 나머지 1
- **기병은 일단 전열만 공격한다** (보병과 같은 대상 규칙). 궁병, 책사, 도사, 풍수사는 전열/후열 모두 노릴 수 있다
- 제로섬 사기: **5:5로 시작, 피해에 영향 없음, 최종 판정에서만 사용** (`maxEffect`를 올리면 피해 보정으로 켤 수 있다)
- 승패: 전멸 군단 수 → 잔여 병력 → 사기 → 방어측, 종료 조건: 전멸 / AP 소진 / 교착 / `maxTurns`
- 진영당 1~6군단 가변 편성, 전열/후열 3+3, 무작위 편성 모드
- 기본 대상 선택 AI: 예상 피해가 큰 적. 기본 가드 AI: 지킬 같은 열 아군(AP가 남은 아군)이 있으면 가드를 100%까지 올려 유지하고 공격하지 않는다. 쓸 수 있는 버프가 있으면 공격보다 먼저 쓴다
- 엔진은 한 행동씩 진행할 수 있다 (`nextActor` / `getLegalCommands` / `preview` / `perform` / `result`). 이것이 수동 플레이의 기반이며, `run()`과 같은 결과를 낸다.

## 아직 구현하지 않은 것

상태이상(화상/독/젖음), 책략의 날씨/지형 변환, 필살기, 승급 병종(방패병 포함), AP 회복(풍수사), 아이템, 군단 경험치.
책략/독연은 현재 피해만 준다. 캐릭터 중에 풍수사는 없다 (곽가를 도사로 바꿨다). 풍수사의 치유와 AP 회복은 버프로 대체하는 방향이라 보류 중이다.

## 현재 기본 수치의 시뮬레이션 관찰 (무작위 편성 1만 회)

수치는 모두 임시값이므로 결론이 아니라 **조정 신호**로 본다. 병종 배율, 곽가 도사 변경(AP 4), 보병 가드, 기병 전열 공격, 책사/도사 버프를 모두 반영한 값이다.

| 병종 | 가드 AI `protect` (기본) 승률 / 생존 | 가드 AI `never` 승률 / 생존 |
|---|---|---|
| 책사 | 42% / 34% | 43% / 34% |
| 보병 | 49% / 74% | 57% / 84% |
| 기병 | 51% / 70% | 47% / **24%** |
| 도사 | 45% / 90% | 45% / 90% |
| 궁병 | **62%** / **100%** | 62% / 100% |
| 평균 라운드 / 공격측 승률 | 4.3 / 51% | 4.0 / 51% |

- **승률은 42~62%로 모였다.** 버프가 책사/도사의 AP를 쓰게 하면서 곽가가 더는 튀지 않는다 (캐릭터별 승률 42~64%).
- **궁병이 가장 강하고 한 번도 죽지 않는다 (생존 100%, 목표 20%).** 기병은 전열만 때리고, 책사/도사는 AP를 버프에 쓰기 때문에 후열의 궁병이 맞을 일이 거의 없다. 궁병을 후열에서 끌어낼 수단(후열을 때리는 병종/스킬)이 필요하다.
- **책사와 도사는 서로 다르게 죽는다 (생존 34% / 90%).** 방어 3으로 예상 피해가 같고 동률이면 병력이 적은 쪽을 고르는데 책사(800)가 도사(1000)보다 적다. 전열이 후열을 못 때리므로 일단 둔다.
- **가드 AI `protect`에서 보병은 거의 공격하지 않는다** (1만 판에서 일반공격 1.3만 회, 가드 5.8만 회). 대신 같은 열 기병이 많이 산다 (24% → 70%). 지킬 아군이 모두 AP를 다 쓰면 공격으로 나선다.
- 이전에 알게 된 것: AI 정책이 결과를 크게 좌우한다 / 전멸로 끝나는 전투는 거의 없다 (판정으로 끝남) / 1대1은 AP 4로 서로 못 죽이고 속도 1 차이가 승패를 가른다 / 전열 전멸 시 후열 이동은 기본 수치에서 거의 발동하지 않는다 / 한 판은 1배속에서 약 1분 (기본 속도 2배).
- `heal.scale`은 그대로(47)라 풍수사가 다시 나오면 치유량(회당 약 370)이 일반공격보다 크다. 풍수사의 치유는 버프형으로 바꾸는 방향이라 보류 중이다.
