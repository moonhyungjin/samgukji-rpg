# 삼국지 × 전국란스 스타일 전략 RPG — 전투 샌드박스

전투 UI는 상단 전장과 하단 양측 카드·중앙 명령 패널로 구성한다. 진영당 3명 이하면 넓은 카드 한 열, 4~6명이면 전열·후열 두 열을 쓰며 로그는 접어서 볼 수 있다.

전장 가독성: 미제작 방패병은 방패 표식과 가드 상태로 구분한다. 군단 이름표는 기병 등 모든 전투 그림 위에 표시되며, 게임 규칙과 별개인 렌더링 정보다. 아트 제작 방침은 [점진적 제작](docs/art/WORKFLOW.md)을 따른다.

현재 단계: **전투 엔진, 시뮬레이터, CLI, Balance Lab, PixiJS 전투 화면(관전 + 수동 플레이) 완료.**
처음 오셨다면 [인계 문서](docs/HANDOFF.md)부터 읽는다. 설계 문서는 `docs/design/`, 원본 기획서는 `docs/spec/`에 있다.
문서 안내: **`GAME_DESIGN.md`** 무엇을 만드는가 / **`TODO.md`** 지금 할 일과 열린 결정 / **`CLAUDE.md`** 개발 규칙(에이전트용, `AGENTS.md`는 요약) / `docs/HANDOFF.md` 구현 현황과 구조.

## 구조

```text
apps/
  game/            React + PixiJS 전투 화면 (관전, 수동 플레이)
  balance-lab/     React + Vite 밸런스 도구 겸 데이터 편집기 (시뮬레이션은 Web Worker에서 실행, 고친 값은 "파일에 저장")
packages/
  battle-engine/   순수 TypeScript 전투 엔진 (React/PixiJS/DOM 의존 없음)
  game-data/       게임 데이터 (data/*.json: 스킬, 병종, 장수, 기본 편성, 밸런스 수치. 특성 정의는 남겨 두었지만 어느 병종에도 붙어 있지 않다) — Lab에서 고치고 저장한다
tools/
  sim/             시뮬레이션 CLI
  e2e/             게임 화면을 실제 브라우저로 조작해 확인하는 스크립트
docs/              HANDOFF.md, design/(설계), spec/(원본 기획서)
```

`battle-engine`은 데이터를 인자로만 받는다. 게임 화면과 Balance Lab이 **같은 엔진**을 쓴다. 화면은 규칙을 계산하지 않고 엔진의 이벤트를 재생하기만 한다.

## 명령어

```bash
npm install
npm test                 # vitest (엔진, 통합, Lab, 게임 로직/패널)
npm run typecheck

npm run game             # 게임 화면 개발 서버 (http://localhost:5174)
npm run game:build       # 게임 프로덕션 빌드 (apps/game/dist)
npm run e2e              # 게임 화면을 실제 브라우저로 조작해 확인 (먼저 npm run game 실행, Edge/Chrome 필요)

npm run e2e:lab          # Lab을 실제 브라우저로 조작해 확인 (먼저 npm run lab              # Balance Lab 개발 서버 (http://localhost:5173). 데이터 편집과 "파일에 저장"은 이 개발 서버에서만 된다
npm run lab              # Balance Lab 개발 서버 (Vite). 터미널에 나오는 주소(보통 http://localhost:5173)를 연다
npm run lab:build        # Lab 프로덕션 빌드 (apps/balance-lab/dist)

npm run sim -- --iterations 1000 --seed 1 --out out/report.json
npm run sim -- --lineups random                  # fixed | random (병종/캐릭터별 승률은 random에서 본다)
npm run sim -- --balance my-balance.json         # defaultBalance에 부분 덮어쓰기 (Lab의 "밸런스만 내보내기" 파일)
npm run sim -- --target-policy lowest-troops     # highest-damage(기본) | lowest-troops | random
npm run sim -- --pool normal                    # elite(기본) | normal(황건적) | all: 무작위 편성의 후보
npm run sim -- --buff-policy opening            # first(기본) | opening(1라운드만 버프) | half(절반 확률) | never(공격만): 책사/도사의 버프 AI
npm run sim -- --guard-policy never              # protect(기본) | never: 가드를 쓸 수 있는 군단의 AI
npm run sim -- --team-a shu --team-b wei --roles alternate   # alternate | A-attacks | B-attacks
```

`--balance` 예: `{ "heal": { "scale": 25 }, "morale": { "defenderStart": 52 } }`

## 게임 화면 (`apps/game`)

`npm run game`으로 열고, 설정 화면에서 편성, 조작할 진영, 시드, 속도를 고른 뒤 전투를 시작한다.

- **관전**: 양쪽을 AI가 조작한다. 속도 0.5~4배 또는 즉시, 재생 중 "건너뛰기".
- **수동 플레이**: 공격측 또는 방어측을 조작한다. 내 군단의 차례마다 멈추고, 스킬을 고르면 **대상별 예상 피해/반격/격파**와 **가드가 막을 확률**이 나온다. 대상은 목록 버튼이나 화면의 노란 테두리 카드를 눌러 고른다. 대기(AP 소모 없음)와 "남은 전투를 AI에게 맡기기"도 있다.
- **카드별 행동 UI**: 군단 카드에 마우스를 올리거나 터치하면 그 대상에게 가능한 행동만 나온다. 적에게는 공격, 아군에게는 가능한 지원, 행동 중인 장수에게는 가드·대기를 표시한다. 중앙에는 차례 안내와 AI 위임을 두며 로그는 하단에서 펼쳐 본다.
- **원거리 연출**: 활 공격은 화살, 책략은 문양, 독연은 연무로 구분한다. 실제 피해 대상(가드 포함)으로 효과를 재생하며, 속도 변경과 건너뛰기를 지원한다.
- **방패병(장비, 허저)이 가드를 쓴다.** 보병(위연, 전위)은 쓰지 않는다. "가드" 버튼을 누르면 올린 뒤의 확률이 표시되고, 카드에 "가드 N%" 배지가 뜬다. 상대가 같은 열 아군을 때리면 확률로 대신 맞는다.
- 화면은 임시 도형이다. 공격측은 왼쪽, 방어측은 오른쪽이고 안쪽 열이 전열이다. 상단에 라운드와 사기 바, 카드마다 병력 바와 AP 칸이 보인다.
- 주소 쿼리로 바로 시작할 수 있다: `?control=attacker|defender|watch&a=shu&d=wei&seed=7&speed=0&autostart=1` (속도 0은 즉시)

## Balance Lab (데이터 편집기 겸용)

`npm run lab`으로 열면(http://localhost:5173) **모든 게임 데이터를 한 곳에서** 고치고, 시뮬레이션으로 확인하고, 마음에 들면 **"파일에 저장"** 으로 프로젝트에 반영한다. 별도의 편집기는 없다.

- **저장 줄**(모든 탭 위): 프로젝트 파일과 다른 점을 보여 준다 (예: "저장 안 됨 (장수 · 병종)"). **파일에 저장**을 누르면 바뀐 파일만 `packages/game-data/data/`에 쓰이고, 게임 화면과 시뮬레이터(`npm run sim`)에 반영된다. **파일 값으로 되돌리기**는 작업 중인 값을 모두 버린다.
- **저장 기록**: Lab에서 "파일에 저장"을 누를 때마다 바뀐 값(경로: 이전 값 → 새 값)과 변경 메모가 `packages/game-data/data/changelog.md`에 덧붙는다. 저장 줄의 "변경 메모" 칸에 바꾼 이유를 적으면 함께 남는다. 에이전트는 작업 시작 전에 이 파일의 아래쪽을 읽어 데이터가 어떻게 바뀌었는지 확인한다
- **저장 전 검사**: 오류가 하나라도 있으면 저장하지 않는다. 장수(id, 이름, 없는 병종, 스탯 0~15 범위), 병종(사거리, 병력 배율, 기본 AP, 없는 스킬/특성, 가드 설정과 가드 스킬의 짝), 기본 편성(1~6군단, 열당 3군단, 없는 장수, 둘 수 없는 열, `shu`/`wei` 필수), 숫자가 아닌 값(스킬/특성/밸런스 수치). 경고(스탯 10 초과, 사거리 1 병종을 후열에 둠)는 저장을 막지 않는다. 기본 편성에서 쓰는 장수와 장수가 쓰는 병종은 삭제할 수 없다.
- **파일이 바뀌면 초안을 버린다**: Lab은 작업 중인 값을 브라우저에 저장해 두지만, 데이터 파일이 바뀌었으면(저장했거나 git으로 받았거나) 그 초안을 버리고 파일 값으로 다시 시작한다. 시뮬레이션 설정, 목표, 편성 슬롯은 유지한다.
- **파일에 저장은 개발 서버가 있어야 동작한다.** 서버 없이 빌드된 화면에서는 "목표 · 가져오기" 탭의 내보내기로 받은 파일을 직접 옮겨야 한다.

| 탭 | 기능 |
|---|---|
| 시뮬레이션 | 1 / 100 / 1,000 / 10,000회 실행, 편성(고정/무작위), 공방 배정, 대상 선택 AI, **가드 AI**, 시드. **수치를 고치면 자동으로 다시 실행**하고 변화량(%p)을 보여 준다. 결과를 기준으로 고정할 수 있다. 목표 지표 점검(경고), 병종/캐릭터/스킬별 통계(캐릭터별 "막음" 포함) |
| 전투 1회 | 고정 편성으로 한 판을 돌리고 라운드별 로그와 최종 상태를 본다 |
| 밸런스 수치 | 피해(공격/방어/지력 저항 계수)/치유/병력/반격/사기/**행동력 → AP**/스탯 곡선 |
| 병종 · 스킬 | **병종 카드**(이름, 계열, 사거리, 병력 배율, 기본 AP, 배치 가능 열, 스탯 보정, 받는 피해 배수, 반격, 스킬/특성, 가드)와 스킬 표(계수, AP, 반격, 가드로 막힘, 방어 무시, 버프) |
| 장수 | 표에서 이름, 병종, 등급(네임드/평범), 레벨, 스탯 8종(공/방/지/속/행동력/외교/내정/매력)을 고친다. 오른쪽 회색 칸은 계산값(**실제 공/방/지/속, 총 AP, 병력, 1회 피해**). 새 장수, 복제, 검색과 등급/병종 필터 |
| 기본 편성 | 편성 카드마다 전열 3칸 + 후열 3칸을 장수 목록에서 골라 짠다. 구성과 병력이 카드에 나온다. 새 편성, 복제, 삭제 |
| 목표 · 가져오기 | 목표 지표 범위(병종별 생존율 목표는 기본으로 모두 꺼져 있다), JSON 가져오기/내보내기, 초기화 |

- 작업 중인 값(초안)과 시뮬레이션 설정은 브라우저 localStorage에 자동 저장된다 (키 `samgukji-balance-lab-v27`).
- **"파일에 저장"을 누르기 전의 값은 Lab 안에서만 보인다.** 게임과 시뮬레이터는 저장된 파일의 값만 쓴다. 저장하지 않고 쓰는 실험은 CLI의 `--balance` 파일이나 "밸런스만 내보내기"로도 할 수 있다.
- 실제 브라우저(Edge 헤드리스)에서 확인했다 (가드 열 추가 전): 워커 자동 실행, 수치를 고치면 결과와 변화량이 갱신되는 것, 모든 탭 렌더링, 전투 1회 로그, 콘솔 오류 없음. (가드/버프 관련 열과 입력란이 생긴 뒤에는 서버 렌더링 테스트로만 확인했고 브라우저에서 다시 열어 보지는 않았다.)

## 구현된 규칙

- 라운드제 + AP 총량, 속도순 행동, 동률은 시드 난수로 결정 (재현 가능)
- 커맨드: 일반공격 / 치유 / **가드** / **버프** / 대기
- 상호 피해(반격): 근접 일반공격만 반격을 받고 원거리(화살/책략/독연)는 일방적으로 공격
- **가드**: 방패병이 처음부터 쓴다. 같은 열 아군을 대신 맞을 확률 (시작 50%p, 가드 한 번에 **지력 × 20%p**, 가드 중에 **맞을 때마다(대신 맞든 직접 맞든) −40%p**, 공격하면 해제. 원작 방식). 책략/독연은 막지 못한다. **가드 상태(확률 > 0)인 동안 받는 피해 ×0.5** (`guard.damageTaken`). 규칙은 `docs/design/02-battle-rules.md` 4장
- **상성표 없음, 병종 특성도 지금은 쓰지 않는다** (순수 스탯 싸움). 특성 체계(`traits.json`, 조건부 피해 보정)는 엔진에 남아 있고 화면에서는 뺐다. 특성은 나중에 추가하기로 했다
- 병력 비례 피해, 전열 전멸 시 후열이 전열로 이동
- **버프**: 책사 "독려"는 아군 하나의 **공/방/지/속 중 무작위 1~3가지를 +1** (전투 끝까지, 한 아군에게 1회), 도사 "결계"는 아군 하나의 **다음 피해 1회를 0으로 무시** (전국란스의 음양사 느낌). 둘 다 AP 1, 병력과 무관하게 아군을 돕는다
- 병종별 병력 배율(원작의 병종별 병력 상한): 궁병 1.5, 방패병 1.2, 도사 0.7, 풍수사 0.7, 나머지 1. 징병 단가(증원/보충/해고, `recruit`)도 병종 데이터에 있지만 전투에서는 아직 쓰지 않는다
- **공격 종류별 받는 피해 배수** (`damageTakenByType`): 물리(일반공격/돌격/화살)와 책략(책략/독연)을 구분한다. 방패병/보병/기병/궁병은 물리 ×1, 책략 ×1.1, 책사/도사/풍수사는 물리 ×1.1, 책략 ×0.8. 물리 공격수(특히 궁병)가 지력 계열을 잡는 전문가가 되고, 지력 계열끼리는 서로 덜 아프다
- **반격 비율은 기술마다 있다** (`skill.counterRate`, 원작 방식): 반격 피해 = 반격자가 공격자를 계수 1로 친 피해(**맞기 전 병력** 기준) × 공격 기술의 반격 비율. 보병 공격과 기병 돌격은 0.25. 생략하면 `balance.counter.rate`(0.5). 보병/방패병/기병만 반격하고 궁병과 지력 계열은 반격하지 않는다
- **평범한 장수(황건적)**: `rank: 'normal'` 캐릭터 12명(병종마다 2명, 스탯이 네임드의 절반 안팎)과 기본 편성 `yellow`. 무작위 편성은 기본으로 네임드 장수만 쓰고 `--pool normal|all`(Lab: "무작위 편성 후보")로 바꾼다
- **초반 시나리오(3 vs 3~4)**: 촉은 유관장(유비 보병, 관우 기병, 장비 방패병, 편성 `shuStart`)으로 시작해 황건적과 싸운다. 황건적은 쉬움 `yellowEasy`(보,보,방), 보통 `yellowNormal`(보,방,궁), 어려움 `yellowHard`(보,보,방 + 궁 후열)로 나눈다. `npm run sim -- --team-a shuStart --team-b yellowHard`. Lab 편성 탭에도 버튼이 있다. 유비는 새 캐릭터(보병, 공7 방6 지6 속5 행동력3 매력10, 임시값)
- **병력 보정 방식** (`balance.troopFactor.mode`): **기본은 `relative`(상대 비교, 2026-10-08 확정)**이고 환산 병력이 켜져 있다 (`normalizeByScale: true`, 병력 배율은 HP만 바꾼다). `tiered`(구간식, 원작 방식)는 유효 병력 = 1000명까지 1명당 1 + 4000명까지 1명당 0.5 + 그 이상 1명당 0.3 (최소 300)이고, 보정 = 유효 병력 ÷ 1000이며 피해가 공격자의 현재 병력을 넘지 않는다. `absolute`는 모든 병종에 같은 기준 병력(1000)을 써서 현재 병력 ÷ 1000(하한 0.3, 상한 1.75)이다. 그래서 최대 병력이 800인 병종은 가득 차도 0.8이다. `relative`(상대 비교)는 공격 스탯 기반 공격은 (내 병력 ÷ 상대 병력)^0.5(하한 0.5, 상한 1.5)로 상대와 비교하고, 지력 기반 공격(책략/독연)과 치유는 상대와 무관하게 내 최대 병력 대비 현재 병력(하한 0.3, 상한 1)만 본다. 가득 찬 병종은 최대 병력이 얼마든 1.0이다. Lab 밸런스 수치 탭에서 방식과 값을 고른다
- **풍수사**: 기본 공격은 **활 공격**(`geomancer-shot`, 공격력 기반, 계수 0.6으로 궁병 0.95보다 약하게, 원거리라 반격 없음)이고, 아군만 치료한다 (치유는 지력 기반). 공격은 공격력으로, 회복은 지력으로 한다. 기본 AI는 병력이 70% 미만인 아군이 있으면 치유를 먼저 하고 없을 때 활을 쏜다. 풍수사 장수는 아직 없다 (`TODO.md`)
- **피해는 실제 병력 수로 계산한다** (원작 방식, `balance.troopFactor.normalizeByScale: false`). 병력 배율이 큰 병종(궁병 1500명)은 그만큼 세게 때린다. 켜면 병력 배율로 나눈 "환산 병력"으로 세어서 병력 배율이 피해에 영향을 주지 않는다
- **병종 스탯 보정** (캐릭터 기본 스탯에 더해짐, `statMods`): 방패병 공−1 속−1 (방어 보정은 제거) / 보병 없음(표준) / 기병 공+1 방+1 속+1 / 궁병 방−1 속−1 / 책사 지+1 / 도사 속+1 / 풍수사 없음. 승급 병종은 자기 보정을 따로 가진다
- **AP = 병종 기본 AP + 캐릭터 행동력 추가 AP.** 병종 기본 AP: 방패병 3, 보병/기병/궁병 2, 책사/도사/풍수사 2. 행동력 스탯(1~10)은 2마다 추가 AP 1 (올림, `balance.action`으로 조정). 예: 행동력 3이면 +2. 캐릭터마다 다르게 둔다. 초반엔 행동력 대체로 5 이하(+3), 10(+5)까지는 아이템 등으로 올리는 방향. 지금 캐릭터 행동력은 방패병/보병/기병/궁병 3, 책사/도사 1이라 총 AP는 방패병 5, 보병/기병/궁병 4, 책사/도사 3
- **기병 돌격 계수 1.2, 대상의 방어를 1 무시한다** (`ignoreDefense`, 물리 공격만). 기병이 받는 피해는 병종의 받는 피해 배수로 정한다 (물리 ×0.855, 책략 ×0.99)
- 병종: 보병과 방패병이 가장 표준적인 병종이다 (방패병 = 보병 + 가드)
- **대상 열에 따른 주는 피해 배수** (`damageDealtByRow`, 병종별): 궁병은 대상이 전열이면 ×0.8, 후열이면 ×1. 나머지 병종은 전열/후열 모두 ×1. 병종 카드의 "줄 때 전열 / 줄 때 후열"에서 고친다
- **사거리**: 공격자와 대상의 거리(전열↔전열 1, 후열↔전열 또는 전열↔후열 2, 후열↔후열 3)가 사거리 이하여야 공격할 수 있다. 방패병/보병/기병은 사거리 1 — 자기가 전열일 때 적의 전열만 칠 수 있고, 후열에 서면 아무도 못 친다. 궁병/책사/도사/풍수사는 사거리 3 — 어느 열에서든 모든 열을 칠 수 있다. 방/보/기/궁은 시작할 때 전열과 후열 어디에든 배치할 수 있고, 책사/도사/풍수사는 후열 전용이다. 전열이 전멸하면 후열이 전열이 된다 (시작할 때 전열이 비어 있어도 마찬가지)
- 제로섬 사기: **5:5로 시작, 피해에 영향 없음, 최종 판정에서만 사용** (`maxEffect`를 올리면 피해 보정으로 켤 수 있다)
- 승패: 전멸 군단 수 → 잔여 병력 → 사기 → 방어측, 종료 조건: 전멸 / AP 소진 / 교착 / `maxTurns`
- 진영당 1~6군단 가변 편성, 전열/후열 3+3, 무작위 편성 모드
- 기본 대상 선택 AI: 예상 피해가 큰 적. 기본 가드 AI: 지킬 같은 열 아군(AP가 남은 아군)이 있으면 가드를 100%까지 올려 유지하고 공격하지 않는다. 쓸 수 있는 버프가 있으면 공격보다 먼저 쓴다
- 엔진은 한 행동씩 진행할 수 있다 (`nextActor` / `getLegalCommands` / `preview` / `perform` / `result`). 이것이 수동 플레이의 기반이며, `run()`과 같은 결과를 낸다.

## 아직 구현하지 않은 것

**상태이상(화상/독/젖음 등 디버프), 책략의 화계 조건(날씨/지형)과 화상 확률, 독연의 독 부여**, 책략의 날씨/지형 변환, 필살기, 승급 병종(방패병 포함), AP 회복(풍수사), 아이템, 군단 경험치.
책략/독연은 현재 피해만 준다. 캐릭터 중에 풍수사는 없다 (곽가를 도사로 바꿨다). 풍수사의 치유와 AP 회복은 버프로 대체하는 방향이라 보류 중이다.

## 현재 기본 수치의 시뮬레이션 관찰 (무작위 편성 1만 회, 시드 3)

**지금은 병종 간 균형을 정밀하게 맞추지 않는다** (`TODO.md`의 방침). 승급 병종, 새 커맨드(일제사격, 저격, 화계, 대화계), 디버프, 징병 비용이 들어오면 판도가 달라지기 때문이다. 아래는 현재 값이 깨지지 않았는지 보는 참고용이다. 수치는 모두 임시값이다.

가드 AI `protect`, 버프 AI `first`(책사/도사가 버프를 먼저 쓴다), 피해 공식 **격차식**(`gap`, 공격 계수 60, 격차 1점당 ±10%), 크리티컬 10% ×1.5, 병력 보정 **상대 비교**(`relative`, 환산 병력 켜짐), 받는 피해 배수 모두 1 기준 (2026-10-08 확정값):

| 병종 | 승률 | 생존 | 평균 준 피해 | 평균 받은 피해 |
|---|---|---|---|---|
| 방패병 | 56.2% | 52.1% | 454 | 1123 |
| 기병 | 55.6% | 38.7% | 1143 | 639 |
| 궁병 | 51.9% | 46.0% | 1330 | 485 |
| 보병 | 47.5% | 30.1% | 734 | 794 |
| 도사 | 44.8% | 23.0% | 17 | 643 |

평균 4.28라운드, 공격측 승률 49.5%. 종료 원인은 전멸 57%, AP 소진 32%, 교착 11%다. 버프 AI를 `never`(공격만)로 하면 전멸 74%, 평균 3.7라운드이고 책사가 승률 51.8%(준 피해 956), 도사 52.1%(준 피해 1079)가 된다. 1회당 피해는 기병 돌격 444, 궁병 화살 461, 보병 공격 289, 책략 592다.

초반 시나리오(유관장 대 황건적, 공격측 유관장 고정, 2천 회, 남은 병력 유관장/황건적): 쉬움 2825/0, 보통 3036/0, 어려움 2526/3. 세 난이도 모두 유관장이 전승한다. 난이도는 계수보다 **적 스탯 ±1**이 훨씬 잘 듣는다 (어려움에서 황건적 스탯 +1이면 유관장이 약 45%를 잃는다).

### 피해 공식 비교 (같은 시드, 같은 무작위 편성)

| 공식 | 전멸 종료 | 비고 |
|---|---|---|
| 처음 공식(`divide`, 공격 계수 60) | 0.3% | 방어가 올라도 피해가 완만하게 줄어 전투가 AP 소진으로만 끝난다. 계수를 100 이상으로 올리면 전멸이 늘어난다 |
| 원작식(`additive`) | 17% (구간식 병력 보정과 함께 37%) | 병종 덧셈 보정이 크고 스탯 격차에 민감하다. 방어가 높으면 피해가 바닥에 붙는다 (황건→유명 34%). 방어 버프 +1이 피해 약 −25% |
| **격차식(`gap`, 기본)** | 11% (크리티컬 포함 16%, 상대 비교 병력 보정과 함께 57%) | 격차 1점당 ±10%, 하한 0.3배. 방어 버프 +1이 약 −10%. 병종 승률은 위 둘과 거의 같고 난이도 구분이 가장 뚜렷하다 |

병종 승률의 모양(궁병/기병 강함, 보병 약함)은 공식과 무관하게 거의 같았다. 공식은 전투 길이와 난이도 구분에 영향을 준다.

- **책사/도사는 기본 AI(버프 우선)에서 거의 공격하지 않는다** (준 피해 48, 17). 사람은 섞어 쓰므로 `first / opening / half / never` 범위로 본다.
- **방패병과 기병이 조금 강하고 책사/도사가 약하다.** 책사/도사는 기본 AI가 버프를 먼저 써서 공격을 거의 안 하기 때문이다. 기병은 사거리 2라 전열에서 적 후열까지 친다.
- **전투의 절반 이상이 전멸로 끝난다** (57%). 처음 공식(절대 병력 보정)은 0.3%였다. 상대 비교 병력 보정, 크리티컬, 공격 계수 60이 전멸을 늘렸다.
- 크리티컬(10% ×1.5)을 켜면 전멸이 11%에서 16%로 늘고 병종 승률은 거의 변하지 않는다.
- 후열에 방패병을 두고 가드 AI `protect`면 후열의 책사/도사가 거의 안 맞지만 전투가 대부분 교착으로 끝난다.
- 풍수사는 치유 계수가 커서 풍수사를 넣은 편성의 승률이 크게 올라간다 (임시 장수로 시험). 장수가 아직 없다.
- 병력 보정 `relative`(상대 비교, 지금 기본)는 `absolute`보다 생존율이 크게 낮다. 큰 군단이 작은 군단을 칠수록 세지기 때문이다.
