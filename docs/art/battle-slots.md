# 전투 화면 구성과 에셋 슬롯 (2026-10-12)

> 상태: **사용자 승인 (2026-10-12). 슬롯 구성, 코드로 그릴 것 구분, 파일 이름 규칙, 해상도 규칙을 이 문서대로 쓴다. 고칠 때는 `battle-slots.json`도 같이 고친다.** 코드(`apps/game/src/render/*`, `components/*`)에서 지금 화면을 이루는 요소를 뽑았다.
> 목적: 화면의 모든 요소에 **이름(슬롯 ID)과 크기, 상태 종류, 그림이 들어갈 파일 이름**을 정해 두고, 슬롯마다 그림을 하나씩 채운다.
> 새 그림을 만들기 전에 이 표에서 슬롯을 먼저 고른다. 표에 없는 그림은 만들지 않는다.
> 표기: **[확정]** 사용자가 정함 · **[기본값]** 지금 코드의 값 · **[미정]** 정해야 함. 좌표는 논리 화면 1280×900 기준이다.
> 그림체는 `WORKFLOW.md`의 "그래픽 방향"(샘플 3번, 어둡고 색이 적은 UI 키트)을 따른다.

## A. 헤더 (y 0~70) — 고정 영역 [확정 구상 2026-10-13, 좌표는 [임시]]

헤더는 화면 폭에 따라 늘어나는 한 장이 아니라 **고정 좌표의 부품을 쌓은 것**이다 (논리 화면 1280×70). 부품마다 슬롯을 따로 갖는다. 아래 표의 좌표는 처음 값이고, **지금 값은 Lab의 영역 편집이 저장한 `battle-slots.json`이 기준이다.**

## 규칙 [확정, 2026-10-12]

1. **슬롯 구성은 위 표대로 한다.** 표에 없는 그림은 만들지 않는다. 필요한 슬롯이 생기면 표와 `battle-slots.json`에 먼저 추가한다.
2. **코드/CSS로 그릴 것은 그림으로 만들지 않는다.** 효과(B5, B6), 경계선(C1), 버튼(E5, E10), 결과 배너(F2) 등 표의 `코드로 그림`. 용량이 안 늘고 크기를 바꾸기 쉽다.
3. **파일 이름:** `<슬롯 ID>_<이름>_<상태>.png` (예: `D1_card-frame_selected.png`). 슬롯 ID로 검색할 수 있다. (지금 있는 그림은 옛 이름 그대로이고, 채택한 것부터 새 규칙으로 다시 만든다.)
4. **해상도:** 슬롯의 표시 크기(위 표)의 **2배까지만** 만든다. 큰 원본을 그대로 싣지 않는다. 이것이 이미지 용량 정책이다.

## 영역 편집 (구현됨, 2026-10-13)

슬롯의 크기와 위치는 **Lab 에셋 검수 → 슬롯별**에서 직접 고친다. 고친 값은 `battle-slots.json`의 `regions`에 저장되고 게임은 그 좌표를 그대로 읽는다 (A 헤더, D 카드 부품, E 지휘 패널).

- **숫자로 고치기:** 게임 화면 위의 "영역 편집"에 가로 위치 x, 세로 위치 y, 너비, 높이 칸이 있다. 논리 화면 1280×900 기준이다.
- **드래그로 고치기:** 게임 화면의 점선 상자(이름표가 붙은 상자)를 끌면 옮겨지고, 네 모서리를 끌면 크기가 바뀐다. 숫자 칸과 같이 움직인다.
- **저장:** "저장 안 한 변경"이 뜬 상태에서 "저장"을 눌러야 파일에 들어가고 게임 화면이 새 좌표로 다시 그려진다. "되돌리기"는 저장 전 값을 버린다.
- **영역마다 고치는 방식(`edit`)이 다르다:** `free` 영역마다 따로 (A1, A5, A6, A7, A9, E1~E7) · `mirror` 왼쪽/오른쪽을 모두 고칠 수 있고, "좌우 대칭 유지"(기본 켜짐)가 켜져 있으면 한쪽을 고칠 때 반대쪽이 화면 가운데 기준 대칭으로 따라옴, 끄면 따로 (A2, A3, A4, A8) · `cards` 첫 카드에서 고치면 카드 12장에 같은 위치로 적용 (D2~D7) · `locked` 코드가 정해서 여기서는 못 고침 (B, C1, D1 카드 크기, E8~E10 …). `follow`는 같은 영역을 쓰는 슬롯이다 (D8은 D1, D9는 D2).
- **맞추기:** 영역 줄마다 "같은 영역 / 같은 크기 / 같은 높이·세로 위치 / 왼쪽 끝 / 오른쪽 끝" 버튼이 있다. 기준은 같은 그룹의 다른 슬롯(예: A2를 A1의 높이·끝에, A3을 A2와 같은 영역에)이고 저장 전까지는 미리 보기다.
- **겹침 순서:** 헤더 슬롯은 `layer`(작을수록 아래)가 정해져 있고 편집기에 "A1 → A3 → A2 → A6 → A7 → A4·A5·A8 → A9"처럼 보인다. 게임 화면의 점선 상자도 이 순서로 겹친다. 순서는 코드가 정하므로 여기서 바꾸지 않는다.
- **위치는 정해 두지 않았다:** "라운드는 정가운데" 같은 배치 규칙은 테스트로 고정하지 않는다. 마음대로 옮길 수 있고, 화면 밖으로 나가면 경고만 한다.
- 이 문서의 표에 적힌 좌표는 처음 값이다. 지금 값은 `battle-slots.json`이 기준이다.

## 제작 명세서와 맞춤 검사 (구현됨, 2026-10-14)

Codex/Gemini는 정확한 픽셀 크기, 투명 배경, "양 끝 장식 + 늘어나는 가운데" 구조를 스스로 맞추기 어렵다. 그래서 **조건을 슬롯에 적어 두고, 명세서로 넘기고, 받은 그림을 자동으로 검사한다.**

- **조건(`spec`):** `battle-slots.json`의 슬롯에 `slug`(파일 이름), `transparent`(투명 배경 필요), `slice`(양 끝 고정 폭), `mirrored`(오른쪽은 반전해서 씀), `variants`(변형)을 적는다. 지금은 A1, A2, A3, A5, A6, A7에 있다. 조건이 없는 슬롯은 명세서와 검사가 없다.
- **제작 명세서:** Lab 에셋 검수 → 슬롯 선택 → "제작 명세서"에서 **명세서 복사**. 파일 이름, 화면 크기와 만들 크기(2배), 투명 여부, 양 끝 고정 폭, 좌우 반전, 겹침 순서(위/아래에 무엇이 오는지), 글자는 그림에 넣지 않는다는 규칙이 한 장으로 나온다. 슬롯의 크기를 영역 편집으로 바꾸면 명세서도 같이 바뀐다.
- **맞춤 검사:** 후보 그림 카드마다 ✓/✗로 비율(슬롯과 8% 안), 크기(표시 크기의 0.9~2.2배), 투명 채널(PNG 알파)이 표시된다. 같은 검사를 명령줄에서도 쓴다: `python tools/art/fit.py A2` (슬롯의 후보 전체), `python tools/art/fit.py 새그림.png A2` (아직 슬롯에 안 넣은 파일).
- **한계:** 투명 "채널"이 있는지만 본다 (안쪽이 실제로 비어 있는지는 눈으로 확인). 양 끝 장식이 늘어나도 어색하지 않은지도 눈으로 본다.
- **크기 맞추기는 만든 뒤에 한다:** 비율이 틀린 그림은 Codex에 다시 맡기기보다 가져오는 단계에서 자르거나 늘려 맞춘다 (Claude 담당).

## 에셋 검수 (구현됨)

Lab의 **에셋 검수** 탭 (`npm run lab`, 개발 서버에서만 동작).

- 이미지마다 **OK / NO / 대기**. 아무것도 안 누르면 대기. 한 번 더 누르면 대기로 돌아간다.
- **NO는 표시만 하고**, 위쪽 **"NO 정리"** 를 눌러야 파일을 지운다. 지우기 전에 확인 창이 뜨고, git에는 남아 있어 되돌릴 수 있다.
- **게임 코드가 파일 이름을 부르는 그림은 NO로 표시해도 지우지 않고** 경고만 한다 (화면이 깨지는 것을 막는다).
- **슬롯별** 보기: 슬롯(D1 카드 틀 등)을 고르면 후보 그림이 나란히 보인다. **미배정** 보기: 어느 슬롯에도 안 들어가는 그림. **전체** 보기와 상태 필터(대기/OK/NO)도 있다.
- 그림 위에는 크기, 용량, 속한 슬롯, "게임이 씀"/"문서가 씀" 표시가 나온다. 그림을 누르면 크게 본다.
- 결과는 `docs/art/review.json`에 저장된다 (`{ "경로": "ok" | "no" }`, 대기는 기록하지 않음).
- 슬롯과 후보 찾는 규칙은 `docs/art/battle-slots.json`의 `match`(경로 패턴). 새 그림이 슬롯에 안 잡히면 여기에 패턴을 추가한다.

## 게임 화면 Viewer (구현됨)

에셋 검수 탭 위쪽의 **"게임 화면에서 보기"** 패널. 실제 전투 화면(`apps/game`의 `?viewer=1`, `ArtViewer.tsx`)을 iframe으로 띄운다. 게임 서버가 켜져 있어야 한다 (`npm run game`, 기본 `http://localhost:5174`, 주소는 패널에서 바꾼다).

- **슬롯 위치 표시:** 슬롯을 고르면 그 슬롯의 화면 영역(`battle-slots.json`의 `regions`, 논리 화면 1280×900 좌표)이 금색 점선 상자로 표시된다.
- **후보 그림 끼우기:** 슬롯에 `artKeys`(게임 텍스처 이름)가 있으면 후보 카드에 **"화면에 적용"** 버튼이 생긴다. 누르면 그 그림을 그 자리에 끼워서 게임 화면을 다시 그린다. 파일은 바뀌지 않는다. **"원래대로"**로 되돌린다. `artKeys`가 둘 이상이면 "끼워 볼 자리"를 고른다.
- **끼워 볼 수 없는 슬롯:** 코드/CSS로 그리는 슬롯(`codeDrawn`)이나 지금 화면에서 그림을 쓰지 않는 슬롯은 영역 표시만 된다.
- **표시되는 화면:** 6대6 시작 상태(전투는 진행하지 않는다). 그림이 있는 유비, 관우, 황건 보병을 앞에 세웠다.
- **연결:** Lab과 게임 화면은 `postMessage`로만 대화한다. 후보 그림은 Lab 개발 서버(`/api/art/file/<경로>.png`, 읽기 허용 헤더 포함)에서 게임 화면이 직접 읽는다.
- **발견한 문제:** Viewer를 만들며 상단 헤더 그림(`ui/header/*`)이 실제 전투에서 한 번도 읽히지 않는 것을 찾았다 (`battleArtKeys`가 전장과 군단 그림만 불렀다). 이제 헤더 그림은 항상 읽는다 (`FRAME_ART_KEYS`).
