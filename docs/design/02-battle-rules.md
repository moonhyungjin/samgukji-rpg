# 전투 규칙 설계 (v0.2)

> 상태: **기획 단계. 코드는 아직 작성하지 않는다.**
> 범위: 군단전만. 캐릭터/병종/상태이상은 `01-character-and-unit.md` 참고.
> 표기: **[확정]** 사용자가 직접 결정 · **[기본값]** 제안했고 이의가 없어 우선 채택 · **[임시]** 수치 가설, Balance Lab에서 조정 · **[미정]** 결정 필요
> 원작(전국란스) 세부는 기억과 스크린샷 해석에 의존한 것이며, 우리 게임의 규칙은 이 문서가 우선한다.

## 1. 전투 구성

- 진영은 **공격측 / 방어측**으로 나뉜다. [확정]
- 각 진영은 **1~6군단**이며 진영마다 수가 달라도 된다 (예: 6 vs 5). [확정]
- 배치는 **전열 3 + 후열 3**. 화면은 안쪽 열이 전열, 바깥쪽 열이 후열 (스크린샷 해석). [기본값]
- **전열이 전멸하면 같은 진영의 후열이 즉시 전열이 된다.** [확정] 전열이 한 명이라도 남아 있으면 이동하지 않는다.
  - 병종의 배치 규칙(`allowedRows`)은 **시작 편성에만** 적용된다. 이동한 뒤에는 궁병이나 책사가 전열에 있을 수 있다.
  - "같은 열"을 쓰는 규칙(가드, 혼란)은 이동한 뒤의 열을 기준으로 한다.
  - 전열 유닛이 쓰러질 때만 확인한다. 처음부터 후열만 있는 진영은 이동하지 않는다. [기본값]
- 전투 입력에 `BattleContext { weather, terrain }`를 둔다. 책사의 책략 효과가 여기에 따라 달라진다. [확정]
- 총 전투 턴 한도 `maxTurns`는 **40** [임시]. 데이터 필드.
- 상위 스펙의 "6v6 고정"은 폐기하고 가변으로 수정한다.

## 2. 라운드 진행

```text
라운드 시작
  → 속도순으로 각 군단이 행동 기회 1회 (AP 0이면 건너뜀)
     커맨드 선택: 일반공격 / 특수행동 / 필살기 / 대기
  → 라운드 종료: 상태이상 틱, 지속시간 감소
종료 조건 확인 → 미종료 시 다음 라운드
```

- 행동 게이지 방식은 **폐기**한다. 속도는 라운드 내 **행동 순서**를 정한다. [확정]
- 한 라운드에 한 군단은 **1번** 행동한다. [기본값]
- 상태이상의 틱과 지속시간은 **라운드 기준**이다. AP가 0인 군단에도 똑같이 적용된다. [기본값]
- 라운드 수가 총 전투 턴이며, 화면의 중앙 세로 게이지가 이 값이다. [확정]

## 3. 행동력 (AP)

- AP는 **전투 전체의 총량**이다. 라운드마다 회복되지 않는다. [확정]
- 캐릭터마다 AP가 다르며 범위는 **3~5**다 (원작 화면 기준). [임시]
- AP 결정 방식은 보류한다. 캐릭터 데이터의 단순 필드 `ap`로 둔다. [확정]
- AP가 0이 되면 그 전투에서 더 이상 행동할 수 없다. [확정]
- 특수한 효과로만 회복된다. **풍수사 승급 A(AP 회복형)**가 담당한다. [확정]
- 임시 수치: 대상 AP +1, 시전자 AP 1 소모, 대상의 최대 AP를 넘지 못함 [임시]. 이 경우 총량이 늘지 않고 **풍수사의 AP를 핵심 유닛(필살기 보유자 등)에게 옮기는 효과**가 된다. +2로 올리면 순증이 생긴다.

### 커맨드 구성

```text
커맨드 = 병종의 일반공격 + (병종/승급 특수행동) + (필살기) + 대기
```

| 종류 | AP 소모 | 비고 |
|---|---|---|
| 일반공격 | 보통 1, 일부는 2 | 병종이 정의. 승급하면 상위 버전으로 교체 (돌격 → 돌격2) |
| 특수행동 | 커맨드별 | 예: 보병의 가드, 책사의 독려(공격+1)와 도사의 결계(방어+1) 버프 (구현됨) |
| 필살기 | **남은 AP 전부** | 유니크 캐릭터만. AP가 1 이상이면 사용 가능, 배율은 고정 |
| 대기 | 0 | 행동을 건너뜀 |

예시 (관우, 기병):
```text
기병      : 돌격 / 대기
중기병    : 돌격2 / 대기
필살기 보유 : 돌격2 / 전력 돌격 / 대기
```

- 필살기는 AP 1개 남았을 때 쓰는 것이 가장 효율적이다. 이를 알고 단순한 규칙을 선택했다. [확정]
- 일찍 쓰면 사망 전에 발동할 수 있고, 늦게 쓰면 효율적이지만 쓰기 전에 죽을 위험이 있다. 이 균형은 Balance Lab의 **필살기 시점 정책 비교**로 검증한다.

### 필살기 구조

- 필살기는 대부분 **장수 캐릭터가 먼저 강력한 공격을 날리고, 이어서 군단의 일반공격이 나가는 2단 구성**이다. [확정]
- **장수 강타(1단계)**는 공격자가 **반격 피해를 받지 않고**(무피해), 피해량이 **자기 병력과 무관**하다(병력 보정 없음). [확정]
- 장수 강타의 가드 무시는 기본으로 하되 밸런스에 따라 조절한다. [확정]
- 2단계 군단 일반공격에 반격 규칙을 적용할지는 [미정]. 기본값은 적용이다.
- 예외: 궁병은 **일제사격**을 필살기로 둔다. **모든 열(전열 + 후열 전체)에 일반공격**을 가한다. [확정]
- 일제사격은 광역이므로 가드를 무시한다. [기본값]
- 데이터는 단계 배열로 표현한다: `ultimate.steps = [{ actor: 'commander' | 'unit', skill, targets }]`.

### 전투 길이 목표

- **짧은 전투가 의도**다. 평균 **5라운드 안팎**을 목표로 한다. [확정]
- 따라서 `maxTurns`(40)는 대기 반복을 막는 안전장치일 뿐이다. Lab에서 값을 줄여도 된다.
- 피해 스케일 역산 [임시]: 6군단이 각자 AP 3~5로 약 4번씩 공격해(약 24회) 병력 약 6,000을 쓰러뜨려야 하므로 회당 약 250이다. 즉 **일반공격 1회 ≈ 대상 최대 병력의 20~30%** 가 목표 규모다.
- 이 값은 Balance Lab에서 `DamageCalculator` 기본 배율을 정하는 출발점이다.

## 4. 타겟팅과 가드

### 기본 타겟팅

1. 공격자가 병종 규칙에 따라 대상을 정한다 (보병과 기병은 전열 우선 — 기병은 일단 전열만, 궁병은 전열 무시).
2. **가드 판정**: 대상과 같은 열(전열/후열)에 가드를 가진 아군이 있으면 대신 맞을 수 있다.
3. 피해를 계산한다.

### 상호 피해 (반격)

- **일반공격은 상호 피해를 낳는다.** 공격을 받은 대상이 살아 있으면 공격자에게도 반격 피해가 들어간다. [확정]
- 반격 피해 = 반격자의 일반공격 피해(반격자의 현재 병력·스탯 기준) × `counter.rate` [임시 0.5]
- 대상이 이 공격으로 쓰러졌다면 반격은 없다. 반격으로 공격자의 병력이 0이 되면 공격자도 쓰러진다.
- **근접 공격(보병/방패병/기병)만 반격 피해를 받고, 원거리 공격(궁병/책사 등)은 일방적으로 공격한다.** [확정] 스킬의 `counterable` 플래그로 표현한다 (근접 일반공격 true, 화살/책략/독연 false).
- 공격받은 쪽이 반격할 수 있는지는 병종의 `canCounter`로 둔다. 현재 보병/기병/궁병 true, 지력 계열 false이며 [임시]다. 확인이 필요하다.
- 필살기의 장수 강타는 반격을 받지 않는다 (아래 필살기 구조).
- 가드로 대신 맞은 경우 반격하는 쪽은 [미정]. 기본값은 실제로 맞은 쪽이다.

### 가드 (가드를 쓰는 병종의 특수행동. 현재는 보병)

구현 완료. 가드를 쓸 수 있는 병종은 병종 데이터에 `guard` 설정이 있고, 스킬의 `guardable`이 켜진 공격(화살/돌격/공격)만 막을 수 있다.

원작의 `ガード 50%` 표시는 **피해 감소율이 아니라 "대신 막아줄 확률"**이다. [확정]

| 규칙 | 내용 |
|---|---|
| 시작값 | 가드를 쓰는 병종은 전투 시작 시 막아줄 확률 **50%p**를 가진다 [확정]. 재생 여부는 [미정] |
| 획득 | 가드 커맨드(**AP 1 소모**)를 쓰면 **+70%p** [확정]. 예: 50 + 70 = 120% |
| 누적 | 여러 번 쓰면 쌓이고, **100%를 넘을 수 있다** |
| 범위 | 같은 열의 다른 아군만 대신 막는다. **광역/관통/책략 공격은 막지 못한다** (일단) [확정] |
| 막았을 때 | 한 번 막으면 확률이 **40%p 감소**한다 (120% → 80%). **막을 때 AP는 소모되지 않는다** [확정] |
| 공격하면 | 일반공격이든 필살기든 **공격 커맨드를 쓰는 순간 가드 확률이 전부 제거**된다 |
| 대기 | 가드 확률은 유지된다 |

즉 가드를 쓰는 군단은 **막기만 하거나 공격만 해야 한다.** 이것이 핵심 선택이다.

> 감소는 **%p를 빼는 방식**이다 (곱하기 0.5가 아님). 예: 120 → 80. [확정]
> 수치(시작 50 / 가드 +70 / 막을 때 −40 / AP 1)는 모두 데이터 필드로 두고 Lab에서 조정한다.

세부 규칙:
- 같은 열에 가드 유닛이 여러 명일 때의 순서: 확률이 높은 쪽부터 판정하고 처음 성공한 쪽이 막는다 [임시, 구현됨]
- **이벤트 순서**: 행동 → 가드 발동(`intercept`) → 확률 감소(`guardChange`) → 피해. 화면 연출이 이 순서로 재생된다.
- **미리보기**: 공격의 피해/반격은 가드가 없을 때(원래 대상이 맞을 때)의 값이고, 가드가 막을 확률(`interceptChance`)을 따로 알려 준다. 막을 수 있는 가드가 여럿이면 `1 − Π(1 − 각 확률)`이다.
- **AI(시뮬레이션과 상대편)**: 가드를 쓰는 군단은 지킬 같은 열 아군(**AP가 남아 아직 싸울 수 있는 아군**)이 있는 동안 가드를 100%까지 올리고, 그 이상이면 대기하며 유지한다 (공격하면 풀리므로 공격하지 않는다). 지킬 아군이 없거나 모두 AP를 다 썼으면 공격한다. [확정] `never`로 두면 항상 공격한다. [기본값] Lab에서 바꿀 수 있다.
- 가드 확률이 100% 이상일 때 판정: 100%는 무조건 성공, 초과분은 막은 뒤 남는 확률로 이어진다 [기본값]
- 가드 유닛이 사망하면 확률도 소멸한다 [기본값]

## 5. 사기

- 상단의 파랑/빨강 바가 사기이다. [확정]
- **양측이 하나의 바를 나눠 갖는 제로섬 구조**다 (한쪽이 오르면 다른 쪽이 내림, 예: 60:40). [확정]
- **시작은 5:5**다. [확정] (이전에는 방어측 우세 60:40이었으나, 시뮬레이션에서 공격측 승률이 38%까지 떨어져 폐기했다.)
- **사기는 피해에 영향을 주지 않는다.** 최종 판정에서만 쓰인다. [확정]
  - 구현에는 피해 보정 폭 `maxEffect`가 남아 있고 기본값 0이다 (Lab에서 켜서 실험할 수 있다). `보정 = 1 + maxEffect × (자기 편 비율 − 50) / 50`
  - 이전 실험: 시작 60:40 + 효과 ±10%에서는 같은 편성끼리 붙여도 방어측이 73% 이겼다. 5라운드 안팎의 짧은 전투에서는 작은 보정도 눈덩이로 커진다.
- 변동 요인 [확정]: **군단 전멸 시 크게 하락**하고, **공격당할 때도 소폭 하락**한다. 피격 하락은 전멸만큼 크지 않다.
  - 임시 수치: 군단 전멸 −8p, 피격 −1p (자기 편 비율이 상대편으로 이동) [임시]
  - 그 외(필살기 성공 등)는 [미정].
- 판정에서의 쓰임은 6장 참고. **판정에 쓰이는 방식은 해석이 들어 있다:** 사기를 판정의 3번째 기준(동률 해소)으로 두었다 (`tiebreak`). 이 경우 사기가 승패를 가르는 일은 거의 없다 (전멸 수와 병력이 모두 같아야 한다). 사기를 더 강하게 반영하려면 `before-troops`(전멸 수 다음에 사기)나 다른 방식을 정해야 한다. [미정]

## 6. 종료와 판정

종료 조건: 한쪽 전멸 / 양쪽 모두 행동 가능한 군단이 없음 / `maxTurns` 도달 / **한 라운드 동안 아무도 대기 외 행동을 하지 않음(교착)**. 앞의 셋은 [확정], 교착은 구현에서 추가한 안전장치로 [기본값]이다. 교착은 AP가 남은 풍수사만 남고 치유할 대상이 없을 때 등에 생긴다.

판정 순서:

1. **전멸한 군단 수가 적은 쪽**이 승리한다 (예: 좌 3군단 전멸 vs 우 2군단 전멸 → 우 승). [확정]
2. 동률이면 **잔여 병력 합산**이 큰 쪽이 승리한다. [확정]
3. 그래도 동률이면 **사기가 높은 쪽**이 승리한다. [기본값 — 사기를 판정에 쓴다는 결정의 해석, 5장 참고]
4. 그래도 동률이면(사기 5:5) **방어측**이 승리한다. [확정]

- `balance.morale.judgement`를 `before-troops`로 두면 2번과 3번의 순서가 바뀐다 (전멸 수 → 사기 → 병력).

- 비교는 절대 수 기준이다. 비율 기준이 더 공정한지는 Lab의 편향 측정으로 판단한다.

## 7. Balance Lab과의 관계

- 사람이 없이 수만 번을 돌리므로 **커맨드 선택 정책**이 필요하다. 정책은 테스트 변수다. [확정]
  - 기본: 항상 일반공격
  - 필살기 늦게: AP 1개 남으면 필살기
  - 필살기 일찍: 첫 행동에서 필살기
  - 방패병: 가드 N회 후 공격 등 (추가 설계 필요)
- 공격측/방어측을 교체해서 돌리는 실험이 기본이다 (동률 처리가 방어측에 유리하므로).
- 날씨/지형은 입력 변수다. 날씨별 책사 승률을 별도로 본다.
- **대상 선택 AI**(예상 피해가 큰 적 / 병력이 적은 적 / 무작위)도 테스트 변수다. 기본값은 **예상 피해가 큰 적**이다. [확정] 궁병 생존율처럼 "누가 맞는가"에 달린 지표는 이 정책이 결정적이다.
- 무작위 편성 모드로 병종별/캐릭터별 승률을 본다 (고정 편성은 편성 편향이 섞인다).
- 감시할 이상 징후: 눈덩이 효과(병력, 사기), 가드 100%+ 누적의 과도한 방어력, 대기 반복으로 인한 `maxTurns` 도달 빈도.
